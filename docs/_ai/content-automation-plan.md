# 博客内容优化与自动化方案

## 一、 现状分析

### 当前博客状态
- **技术栈**: Jekyll + GitHub Pages（静态站点）
- **主题**: 糖尿病知识（YMYL领域，需特别注意内容质量）
- **问题1**: 内容机械、重复，AI生成痕迹明显，有内容农场风险
- **问题2**: 自动化程度低，缺乏持续的输入源和发布管线

---

## 二、 解决"内容机械重复"问题

### 核心思路：建立记忆机制 + 多样化输入

### 方案 A：向量数据库防重复系统

**目标**: 每次生成文章前进行相似度检索，避免内容重复

**实施步骤**:
1. 部署轻量级向量数据库（ChromaDB 或 pgvector）
2. 将博客现有文章全部向量化存入数据库
3. 每次 AI 生成前：
   - 将选题的核心关键词进行向量化
   - 在数据库中检索相似度 > 80% 的历史文章
   - 如果重复 → 放弃选题 或 强制改写角度

**技术栈**: ChromaDB + Python脚本

### 方案 B：多样化输入源矩阵

**目标**: 摆脱"凭空想象"式生成，输入源必须是活的、结构化数据

**数据源清单**:

| 数据源 | 用途 | 采集方式 |
|--------|------|----------|
| Reddit (r/diabetes, r/Type1Diabetes) | 真实用户痛点 | 爬虫抓取 .json 接口 |
| Diabetes Daily Forum | 用户讨论与争议点 | 定期爬取"Diet & Nutrition"板块 |
| PubMed (医学文献) | 权威背书，解决E-E-A-T | RSS订阅 + AI摘要 |
| Amazon (智能血糖仪新品) | 产品评测、联盟营销 | Amazon Product API |
| ScienceDaily Diabetes News | 科研成果解读 | RSS订阅 |

### 方案 C：Prompt 变异池

**目标**: 同一主题生成不同风格、不同角度的内容

**实现方式**:
1. 建立 Prompt 配置表，包含多种变体：
   - **体裁变异**: 对比清单、Step-by-step教程、避坑指南、选购指南
   - **视角变异**: 
     - "预算有限的实用主义者"（侧重性价比）
     - "资深糖友"（侧重真实体验）
     - "医学研究者"（侧重数据和研究）

2. 每次生成时随机选择组合

### 方案 D：YMYL 领域护栏（针对糖尿病主题）

**必须加入的安全措施**:
1. **免责声明**: 每篇文章自动插入 "本文由AI辅助生成，仅供信息参考，不构成医疗建议"
2. **内容拦截**: 禁止生成具体用药剂量、停药建议
3. **主攻方向**: 锁定边缘辅助领域（无糖食谱、血糖仪评测、特制食品推荐、智能穿戴）

## 三、 解决"自动化程度不够"问题

### 核心思路：建立感知→生成→发布 的完整工作流

### 方案一：架构设计

```
[数据采集层] → [处理层] → [生成层] → [发布层]
    ↓            ↓           ↓          ↓
  RSS爬虫    向量检索    Prompt池    Git Push
  API抓取    去重过滤    LLM生成    CI/CD
```

### 方案二：具体组件

#### 1. 调度与编排中枢 (Conductor)
- **技术**: Python 或 Go 常驻服务
- **功能**: 
  - 定时触发数据采集任务
  - 管理任务队列（采集→生成→发布）
  - 处理 API 限流和重试

#### 2. 数据采集模块 (感知层)
- **Reddit 爬虫**: 抓取 `.json` 接口，提取用户提问作为选题
- **RSS 监控**: 监控 PubMed、ScienceDaily 新论文
- **Amazon 新品**: 抓取血糖仪等新品数据

#### 3. 生成模块 (大脑层)
- **向量检索**: 生成前先去重
- **Prompt 变异**: 随机选择体裁和视角
- **LLM 调用**: Gemini API 生成内容

#### 4. 发布模块 (管道层)
- **静态站点**: 生成 Markdown → Git Push → GitHub Actions 自动构建
- **Front Matter**: 自动注入 title、date、tags、categories
